#+title: Consortium
#+description: Prolog-RLM-backed orchestration for independent model workers, durable reasoning artifacts, and gated ADARD/RAGE execution.

* Consortium

Consortium is a control plane for agentic work where multiple language-model workers operate with fresh context while durable state lives outside any one model conversation.

The initial workflow is ADARD:

1. *Analyze* — establish repository state, evidence, constraints, unknowns, and a bounded problem statement.
2. *Design* — produce an implementation-ready design from the promoted analysis artifact.
3. *Adversarial Review* — independently attack the design, evidence, assumptions, security, failure modes, and testability.
4. *Resolve* — adjudicate the design and review into an explicit decision gate: approve, revise, research, or reject.
5. *Develop* — realize an approved design TDD-first.
6. *Verify* — independently verify the exact implementation head. Verification is a terminal gate, not shared-context self-review.

RAGE (Recursive Analysis with Gated Execution) is an escalation workflow that may be invoked when evidence or verification shows that another bounded analysis/design cycle is required. A local implementation defect does not automatically restart architecture research.

* Architecture

#+begin_src text
user goal
   |
   v
Prolog-RLM / Consortium supervisor
   |
   +-- durable facts, budgets, authority, lineage
   +-- immutable phase input packet
   |
   v
fresh-context phase worker
   |
   v
durable phase artifact
   |
   v
deterministic gate
   |
   +-- next ADARD phase
   +-- bounded revision/research
   +-- RAGE escalation
   `-- terminal result
#+end_src

No phase worker inherits another worker's hidden chat transcript. Cross-phase knowledge must be carried through explicit artifacts, evidence references, and the durable Prolog knowledge base.

* Async harness

The harness is a persistent JSON Lines stdio process intended for Emacs
=make-process=. Starting a run admits the first Prolog-RLM Future and returns a
stable run ID without waiting for model work:

#+begin_src sh
nix run . -- --help
nix run . -- daemon --memory
#+end_src

Protocol requests have ={id, method, params}= and responses carry the same
=id=. The process also pushes ={kind:"event", event:{...}}= records. Supported
methods are =start=, =status=, =events=, =artifact=, =cancel=, =subscribe=,
=unsubscribe=, and =shutdown=.

Every phase is a separate =rlm_completion:llm_query_async/3= Future with a fresh
session ID and one explicit packet. A completion callback records immutable
Prolog-RLM artifacts and submits the next admitted phase; Consortium does not
own a scheduler or thread pool. Cancellation revokes the current attempt fence
before cancelling the active Future, so late output cannot advance state.

Tests use deterministic =fake(...)= workers. Trusted embedding code may select
=rlm(Provider, ProviderName)= for direct provider execution or
=completion(Options)= for Prolog-RLM typed plans, tools, and subagents. Role to
model descriptors remain Consortium configuration in =consortium.toml= or the
run's =models(...)= option.

* Invariants

- Prolog owns workflow state, transition legality, budgets, authority, lineage, cancellation semantics, and durable facts.
- Models produce proposals and observations; model prose never becomes executable authority by itself.
- Every phase receives an immutable, bounded input packet.
- Every phase worker starts with fresh model context.
- Cross-phase context is explicit and inspectable.
- Design cannot begin without an analysis artifact.
- Development cannot begin without an approved resolve decision.
- Verification runs against an exact implementation identity.
- Failed verification is classified before escalation; local bugs go to bounded repair, architectural failures may re-enter ADARD/RAGE.
- No silent context sharing, silent capability widening, or unbounded recursion.
